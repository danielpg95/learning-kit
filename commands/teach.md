The user wants to deeply understand: $ARGUMENTS

Teach this concept using the following structure:

1. **One-sentence definition** — what is it, plainly
2. **Analogy** — compare it to something from everyday life or from Rails
3. **Why it exists** — what problem does it solve? What was life like before it?
4. **Minimal example** — the smallest working example (under 20 lines)
5. **Real-world usage** — how it's actually used in production code
6. **Common mistakes** — what do beginners get wrong with this?
7. **Where to go deeper** — one specific resource (docs page, not a generic
   "check the docs")

The user comes from a Ruby on Rails background. Frame everything through
that lens when possible.
